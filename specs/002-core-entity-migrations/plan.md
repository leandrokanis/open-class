# Implementation Plan: Core Entity Migrations (Courses, Modules, Lessons, Enrollments)

**Branch**: `Nautilus` | **Date**: 2026-05-16 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-core-entity-migrations/spec.md`

## Summary

Adds four new Drizzle ORM schema tables (`courses`, `modules`, `lessons`, `enrollments`) to the `@open-class/db` package, with cascading deletes, ordering by `position` integer, slug uniqueness, and a unique composite constraint on `(studentId, courseId)` in enrollments. No new API endpoints are introduced in this feature — it is schema-only, establishing the database foundation for all subsequent course-related features.

## Technical Context

**Language/Version**: TypeScript 5.7 / Node.js 20

**Primary Dependencies**: Drizzle ORM 0.39, drizzle-kit 0.30, pg 8.x, NestJS 11 (API host)

**Storage**: PostgreSQL via `@open-class/db` package (`packages/db/`)

**Testing**: Vitest 3.x (configured in `apps/api`); integration tests require a live PostgreSQL instance

**Target Platform**: Linux server (Docker-based)

**Project Type**: web-service — schema migration layer of a NestJS + Drizzle monorepo

**Performance Goals**: Schema must support 10k+ concurrent users; indexes on FK columns and slug

**Constraints**: Cascading deletes required (FR-008); slug uniqueness enforced at DB level; unique enrollment per student-course pair (FR-006); migrations must be reversible (SC-006)

**Scale/Scope**: 4 new tables, ~5 schema files, 1 migration SQL, 4 integration test files
